How I work

The habits I bring to every ML and AI project, and where you can see them in my work.

01

Find the real problem

Before I pick a model, I work out what decision the output feeds and where the data really comes from. Most failures start with solving the wrong thing.

Seen in: data-quality pipelines at Manifoldz
02

Ground every answer

An answer should trace back to a source record. I use retrieval, citations and guardrails so a system says "I don't know" instead of guessing.

Seen in: RentGuard, Audit Readiness AI
03

Measure, don't assume

I compare approaches on a benchmark before choosing one, then keep the numbers so the choice can be defended later.

Seen in: Quantamind, 92.5% with LoRA vs 85.3% with prompting
04

Break it, then ship it

Real data is messy, so I hunt for the edge cases on purpose. Fix the failure, add a test, and only then call it done.

Seen in: RentGuard's address check and its offline tests
